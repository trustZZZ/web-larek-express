# Справочник маршрутов и кодов ошибок

Эталонная таблица для проверки API Web Larek (backend).

| Роут | Запрос | Действие | Ошибки |
|---|---|---|---|
| `/product` | GET | Запрос возвращает все товары из базы данных. | 500 — ошибка по умолчанию. |
| `/product` | POST | Запрос создаёт новый товар по переданным параметрам. | 400 — переданы некорректные данные при создании товара.<br>401 — ошибка аутентификации.<br>409 — ошибка при создании товара с уже существующим полем `title`.<br>500 — ошибка по умолчанию. |
| `/product/:productId` | PATCH | Запрос обновляет товар по ID, переданному в URL. | 400 — переданы некорректные данные при обновлении товара.<br>400 — переданный `_id` товара невалиден.<br>401 — ошибка аутентификации.<br>404 — товар с переданным `_id` не найден.<br>409 — ошибка при обновлении товара с уже существующим полем `title`.<br>500 — ошибка по умолчанию. |
| `/product/:productId` | DELETE | Запрос удаляет товар по ID, переданному в URL. | 400 — переданный `_id` товара невалиден.<br>401 — ошибка аутентификации.<br>404 — товар с переданным `_id` не найден.<br>500 — ошибка по умолчанию. |
| `/auth/login` | POST | Запрос аутентификации пользователя. | 401 — ошибка аутентификации.<br>500 — ошибка по умолчанию. |
| `/auth/register` | POST | Запрос регистрации пользователя. | 400 — переданы некорректные данные при создании заказа.<br>409 — ошибка при создании пользователя с уже существующим полем `email`.<br>500 — ошибка по умолчанию. |
| `/auth/token` | GET | Запрос получения нового access-токена пользователя. | 401 — ошибка аутентификации.<br>404 — пользователь не найден.<br>500 — ошибка по умолчанию. |
| `/auth/logout` | GET | Запрос выхода пользователя из аккаунта и удаления refresh-токена. | 401 — ошибка аутентификации.<br>404 — пользователь не найден.<br>500 — ошибка по умолчанию. |
| `/auth/user` | GET | Запрос получения данных текущего пользователя. | 401 — ошибка аутентификации.<br>404 — пользователь не найден.<br>500 — ошибка по умолчанию. |
| `/upload` | POST | Загрузка файла во временную папку. | 401 — ошибка аутентификации.<br>500 — ошибка по умолчанию. |

## Примечания к сверке

- В исходной таблице `PATCH` и `DELETE` были указаны как `/product/product/:productId`. Фактический маршрут в приложении — `/product/:productId` (префикс `/product` подключается в `app.ts`, параметр назван `productId`).
- `/upload` по таблице требует код `401`, то есть на маршрут должна быть навешана мидлвар авторизации `auth` в дополнение к `fileMiddleware.single('file')`.
- Коды успешных ответов в таблице не приведены: `POST /product` — 201, `PATCH`/`DELETE /product/:productId` — 200.
